# 踩坑清单（14 条，全部来自真实故障）

> 共同特征：**不报错、只出错**。数据看起来正常、回测照跑、结果像模像样，但数字是错的。
> 每条都给出「症状 / 根因 / 处置」。校验器 `scripts/validate_data.py` 已覆盖其中可自动检测的部分。

## 数据口径类

### 1. 换手率小数 vs 百分数混用
- **症状**：同一套因子在一部分标的上数值差 100 倍；"换手率 > 12%"这类阈值永不触发。
- **根因**：新浪口径是小数（0.0433 = 4.33%），东财是百分数。
- **处置**：按量级判断（`max < 1.5` → ×100），**不要硬编码乘数**。校验器 C4 会告警。

### 2. 市场级序列的"假常数"（最隐蔽）
- **症状**：某市场因子大段"没有变化"，gate 规则据此长期处于"关闭"状态。
- **根因**：akshare 的**深市**两融在 2024-06~2025-06 系统性缺 177 个交易日；
  "两市合计 + ffill"把缺口填成常数 → 20 日变化恒为 0。
- **处置**：改用**完整的沪市单边**序列（占全市场约 51%）。**不要把 ffill 当作修复** ——
  它只是把缺失藏起来。校验器 C3 会报"最大连续缺口"。
- **实测影响**：本研究发现该缺陷曾把 gate 差异从 +1.29pp 夸大到 +1.82pp、p 值从 0.043 虚高到 0.007。

### 3. 金额单位（元 / 万元 / 亿元）
- **症状**：两融、成交额差 1e4 或 1e8 倍，因子之间量纲不可比。
- **根因**：akshare 部分接口返回**元**，部分返回**万元**；东财资金流是**万元**。
- **处置**：落盘时统一为亿元；校验器 C4 按量级告警。

### 4. 文本列被 `to_numeric` 静默清空
- **症状**：大宗交易的买方/卖方席位列**全部为空**，或 `object` 列变成 NaN。
- **根因**：对整张表做 `pd.to_numeric(errors="coerce")`，字符串被强制转为 NaN。
- **处置**：只对数值列转换（白名单/黑名单，见 `fetch_ashare.to_numeric_cols`）。

### 5. 拼接后整段 NaN
- **症状**：把短表与全长序列 `pd.concat(axis=1)` 后，输出行数暴增且早期行全 NaN。
- **根因**：`concat` 按索引**并集**对齐；短表以外的行填 NaN。
- **处置**：短表先 `reindex` 到主表索引；或用 `join`/`merge(how="left")`。

## 时序 / 前视类

### 6. 前视偏差：用了当日收盘后才有的数据
- **症状**：回测结果好得不真实，换手极高的策略也能赚钱。
- **根因**：融资融券、龙虎榜、大宗交易均为**交易所晚间披露**，T 日收盘时决策用不到。
- **处置**：晚间披露类统一 `shift(1)`；股东户数按"报告期 + 45 天"。**海外数据反而更宽松**：
  美市 T 日 16:00 ET 收盘 = 北京 T+1 凌晨，用于中国 T+1 开盘决策无前视。

### 7. "事后确认"被当成"实时可得"
- **症状**：波段/形态类真值标注看似精确，据此评估出的检出率高得离谱。
- **根因**：ZigZag 等转折点的确认要等价格反向走够阈值（实测滞后 4~10 个交易日）。
- **处置**：标注时**同时记录 `confirm_date`**，评估时承认这个滞后；不要用真值反推可实现收益。

### 8. 停牌 / 涨跌停未建模
- **症状**：回测在涨停日"买进"、跌停日"卖出"，实际不可能成交。
- **根因**：引擎只处理了价格，没处理可成交性。
- **处置**：按开盘价相对前收盘判断（创业板 ±19.9%、主板 ±9.9%）跳过不可成交的调仓；
  停牌期用 `ffill` 时**限制最大填充长度**，避免掩盖长期停牌。

## 代码工程类

### 9. 回测满仓买不进（初始资金太小）
- **症状**：策略恒定 0 收益、基准也是 0 —— 完全没成交。
- **根因**：引擎按**整股**成交，而初始资金设为 1.0 元，买不起价格 4 元的股票。
- **处置**：初始资金给足（如 100 万），并按**可用现金**（含手续费）折算可买股数。
- **自检**：先验证"买入持有"基准的收益 ≈ 价格涨幅 - 成本。

### 10. 运算符优先级：`a & b <= c` 不是 `a & (b <= c)`
- **症状**：某个过滤条件完全失效，所有特征被静默跳过。
- **根因**：Python 中 `&` 优先级高于比较运算符。
- **处置**：布尔索引一律加括号。若发现"所有特征都被跳过"，第一反应查这个。

### 11. 循环变量遮蔽
- **症状**：`df.loc['2026-09-01':'2026-09-11']` 报 `cannot slice with [I]`。
- **根因**：`for a, b in (("IS", IS), ("OOS", OOS))` 把标签元组解包成了 `a="IS"`。
- **处置**：`for label, (a, b) in (...)`。

### 12. 模块级常量里的负数常量被 AST 安全门拒绝
- **症状**：策略文件被框架拒绝加载，报"Executable top-level statement Assign is not allowed"。
- **根因**：某些框架（如本仓库 backtest runner）只允许**字面量**赋值，
  而 `-13.0` 在 AST 里是 `UnaryOp(USub, Constant)`，不算字面量；`if __name__` 块也不算。
- **处置**：把常量表写成**函数返回 dict**；把 CLI 演示拆到独立文件。

### 13. 配置类 `dip_size: 0.0` 与 `dip_set: "none"` 语义重复
- **症状**：改了一个开关没效果，因为另一个开关把它短路了。
- **处置**：同类开关只保留一个真相来源；预设表里只改该来源。

## 研究结论类（会毁掉整个研究，比数据错更贵）

### 14. "过滤既有轨迹" ≠ "用受限信号集重跑状态机"
- **症状**：把"只保留部分子策略"的变体算得很好，接入实盘逻辑对不上。
- **根因**：常见做法是**先跑全集合状态机，再在某些日子把仓位清零**。这个做法**只能删不能加**：
  受限子策略本应在某日发生的**新入场**，如果全集合当天没有入场，轨迹里就不存在这一天，于是被永久丢掉。
- **实测**：本研究因此高估了精简版收益（1050.6% vs 正确 861.6%），并让两个结论方向性错误。
- **处置**：**用受限信号集重跑状态机**（传 `dip_mask` 之类的参数），而不是事后筛轨迹。
- **配套防御**：
  1. **留一条回归校验**：已知配置必须复现已知数字（本研究用 966.47%）。
  2. **两份独立实现交叉验证**：全集合配置下必须逐 bar 一致。
  3. **代码以文件为准**：本研究曾出现"读输出以为是减号、文件里是加号"的符号错误，
     导致离场条件变成 `close < MA20×1.05`（几乎天天触发），交易数 33→84、收益 966%→254%。
     **改完立刻跑回归校验，不要靠记忆判断代码对不对。**
